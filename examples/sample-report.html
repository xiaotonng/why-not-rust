02Key evidence

The diff kernel is a real owned-CPU hotspot behind a clean seam

CPU profile of the large-diff (>8k lines) path: 31% of the frame budget lands in the Myers main loop of src/diff/engine.ts; pure struct-in/struct-out, no DOM dependency — an ideal extraction candidate.

src/diff/engine.ts:214 · profiles/big-diff.cpuprofile

The worker-pool attempt lost 41% to serialization tax

worker_threads parallelism sped compute up 2.6×, but structuredClone boundary overhead gave 41% back. Shared-memory / zero-copy layouts are exactly the Rust(wasm) side’s strength.

bench/diff-workers.md

Interactive jank is layout thrash, not compute

Scroll/expand profiles: 58% of time in style/layout/paint, JS compute only 17%. No language change touches this — it needs virtualization and batched DOM writes.

profiles/scroll-jank.cpuprofile

The distribution chain requires the single-file binary; native deps are off-limits

The CLI ships as a Node SEA single binary and the core package allows Node built-ins only. A napi route can live only in the server layer; wasm is the one shape that leaves the distribution chain intact.

core/package.json · scripts/build-sea.sh

03What Rust buys / doesn’t buy here

Buys

  • 6–20× on the diff kernel: zero-copy + SIMD + rayon data-parallelism (precedent range: pydantic-core 5–50×, HF tokenizers).
  • Kills the serialization tax: wasm linear-memory sharing replaces the structuredClone boundary.
  • Deterministic latency in the kernel: no GC jitter inside the diff (incidental — GC is not the observed bottleneck today).

Doesn’t buy

  • Scroll / interaction smoothness: 58% of time is in the browser layout pipeline; the language is not in the room.
  • Memory safety: TS is already memory-safe; residual risk sits in 2 native deps, not app code.
  • Startup & distribution: the SEA single binary already satisfies it; Rust would break the working esbuild chain instead.
  • A smaller Electron baseline: that is a shell decision (the Tauri question), independent of app-code language.

04Matched precedents

VS Codestayed & won

The giant Electron+TS app got fast via process isolation, virtualization and incremental layout — the existence proof that interaction-layer speed is an architecture problem. Its C++ text-buffer experiment was abandoned: “We tried. It didn’t work out for us.”

code.visualstudio.com/blogs/2018/03/23/text-buffer-reimplementation
pydantic-corehybrid win

Kept the Python API, sank only the validation core into Rust: large gains, zero ecosystem migration cost — the same shape as this project’s diff kernel.

docs.pydantic.dev/latest/blog/pydantic-v2-final/
Prismafailed / reverted

Deleted its Rust query engine in 2025 and got 3.4× faster in TypeScript — the JS↔Rust boundary serialization was the bottleneck. The cautionary bound on any chatty-boundary design.

prisma.io/blog — Rust-to-TypeScript engine posts (2025)
fish shell 4.0migrated (honest)

Full Rust rewrite motivated by thread-safety and contributor experience; the team states performance is roughly at parity — the honest cost baseline for whole-rewrites: years, everyone, no perf story.

fishshell.com/blog/rustport/

05Recommended path (smallest sufficient step)

Exhaust the current stack first: histogram diff + batched DOM writes

One-week benchmarks each for the Myers→histogram algorithm swap and the layout-thrash fix; these are the two biggest negative-index sources and the control group for any migration decision.

~2 wks · zero risk

wasm diff-kernel PoC with a boundary budget

Compile the diff kernel rust→wasm. Acceptance threshold written down in advance: end-to-end (including boundary serialization) ≥4× or it does not count — this prevents a 10× kernel from being eaten by the boundary tax.

~2 wks · disposable

Only if that falls short: napi-rs, server layer only

If wasm is limited by linear-memory copies, the server layer allows native deps; napi-rs zero-copy Buffers pass straight through. The CLI’s SEA chain stays untouched.

~2 wks · local

Re-assess; full migration enters only if ②③ both miss and a new hard constraint appears

E.g. a no-runtime embedding requirement or fleet-scale density economics. Otherwise the EXTRACT boundary stands.
